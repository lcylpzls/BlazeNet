# BlazeNet 结构化需求清单

> 状态：初审版 v1.0（待人工审核）
> 日期：2026-08-26
> 依据：00-AI辅助软件开发全流程标准化手册 阶段2

## 1. 核心需求（FR）

### FR-01 制作机分块与差异生成

- 场景：运营/制作人员在制作机生成新游戏或新版本内容。
- 输入：游戏目录（最新版 + 上一版完整文件）、版本号。
- 输出：版本 `.gameindex`（文件→块序列、块哈希→文件偏移、文件哈希）、待上传差异块清单。
- 约束：制作机本地保留最新 + 上一版完整文件（磁盘保障由运营负责）；FastCDC 参数 min 64KiB / avg 1MiB / max 4MiB；块哈希 BLAKE3。
- 验收：对同一游戏的两个版本，未变化区域不产生新块；变化区域块哈希与文件内容一致。

### FR-02 制作机上传与秒传

- 场景：制作机把差异块上传到原始节点。
- 输入：块哈希列表、块数据、版本清单（commit 请求）。
- 输出：原始节点入库的块；已存在块跳过（秒传）。
- 约束：gRPC 双向流、按块断点续传、每块独立确认；上传前先批量查询已存在块；块校验以块哈希为准。
- 验收：重复上传同哈希块不产生重复传输；断点后只重传未确认块。

### FR-03 版本发布与上传中保护

- 场景：游戏处于上传中/版本提交阶段。
- 输入：制作机 commit 版本清单。
- 输出：调度中心发布新版本；上传期间该游戏禁止下载。
- 约束：版本级发布（所有块齐全且哈希校验通过后才可见）；上传中调度中心临时禁止该游戏请求；节点/网吧已有该游戏下载任务被取消并记录日志。
- 验收：commit 前节点无法获取该版本；上传中发起下载被拒绝；进行中任务被取消并留日志。

### FR-04 原始节点/IDC 块库存储

- 场景：原始节点与 IDC 保存内容块。
- 输入：新块数据、版本索引。
- 输出：每游戏一个 `blocks.pack` 大文件 + 每版本 `.gameindex`。
- 约束：块追加写入、同哈希复用；每块位置保留当前 + 1 个历史块；垃圾占比超过可配置阈值（默认 30%）且空间足够时整文件压缩，空间不足推迟；原始节点磁盘空闲低于阈值（默认 50GB）拒绝新上传并告警。
- 验收：压缩后索引只含存活块；空间不足时压缩推迟且不影响读服务。

### FR-05 IDC 纳管与多源分发

- 场景：新游戏/新版本发布到 IDC。
- 输入：全局热度榜、IDC 空闲阈值、版本块清单。
- 输出：IDC 纳管游戏列表与下载任务；块账本更新。
- 约束：按热度纳管；低于空闲阈值不再纳管新游戏，已纳管游戏更新照常；不同 IDC 同时下载不同文件/不同块，块拥有后立即可供其他 IDC；下载优先其他 IDC，全部没有则从中心拉；网吧选择但 IDC 均未纳管时后台标"暂不可下载"（不做自动补拉）。
- 验收：中心出口约等于一份全量；多 IDC 并发拉不同块并互供。

### FR-06 网吧服务器缓存与更新

- 场景：网吧管理员选择游戏、自动更新、回滚。
- 输入：管理员勾选、新版本发布通知、回滚指令。
- 输出：网吧服务器真实游戏文件。
- 约束：一期不做自动推送，只人工选择；每节点可同时处理游戏数按节点配置（默认 5），超出排队；已纳管游戏自动更新；统一流程"拉索引→对账→清理→补缺→合并"；合并=同目录临时扩展名文件 + 文件哈希校验 + 原子替换；临时块 24 小时后删除，之后按真实文件偏移服务；回滚到上一版。
- 验收：更新只下载缺失块；合并失败保留旧文件并重试；回滚后文件哈希与旧索引一致。

### FR-07 块级上传服务

- 场景：节点向其他节点提供已拥有的块。
- 输入：对端批量块请求（哈希列表）。
- 输出：按序流式返回块（长度 + 数据）。
- 约束：下载完成即可供上传（无需等整游戏合并）；合并后临时块保留 24 小时作为源，之后从真实文件偏移读；relay-only 连接拒绝传块；未注册节点不下发 peer 列表。
- 验收：多源并行下载正确；relay-only 连接不传输块数据。

### FR-08 调度中心控制面

- 场景：节点注册、收任务、报状态、对账。
- 输入：节点心跳、注册信息、任务确认。
- 输出：任务流（长连接推送）、心跳摘要比对、重发任务。
- 约束：gRPC 长连接 + 服务端推送，断线重连后全量拉取当前任务；心跳 25 秒、连续 3 次判离线；块级重试 3 次（1/2/4 秒退避）后换源，游戏任务失败置状态由人工重发；调度中心数据每日备份。
- 验收：断线重连不漏任务；失败任务可人工重发。

### FR-09 多地址保活

- 场景：调度中心探测节点多 IP 地址可用性。
- 输入：节点地址表（配置/同步为主，STUN 仅辅助默认链路）。
- 输出：地址可达性状态；不可达地址从下发列表剔除。
- 约束：25 秒一轮、窗口均摊；连续 3 次失败剔除；ping 用轻量 UDP 探针（节点独立 ping 端口），只测声明可入站地址；周期/次数可配置。
- 验收：坏地址约 75 秒内被剔除，恢复 pong 后自动加回。

### FR-10 Web 管理后台

- 场景：管理员管理账号/场所/分组、节点、游戏、任务、状态。
- 输入：管理员操作。
- 输出：后台页面与审计日志。
- 约束：一期 5 模块（账号/场所/分组、节点管理、游戏管理、任务管理、基础状态页）；用户-场所多对多、用户-分组多对多、分组-场所多对多；分组仅批量管理不隔离游戏可见性；关键操作记录审计日志；一期不分角色。
- 验收：绑定关系正确；关键操作可追溯。

## 2. 次要需求（SR）

- SR-01 热度统计：一期只统计启动次数，网吧服务器 5 分钟上报一次（开发期 mock 数据），调度中心 10 分钟重算热度榜。
- SR-02 后台节点参数配置：并发游戏数、磁盘空闲阈值、地址表、压缩阈值等按节点可配置。
- SR-03 基础监控：节点心跳摘要、下载中任务、错误列表展示；不做告警和图表。

## 3. 兼容需求（CR）

- CR-01 原始节点/IDC：Linux（systemd）；网吧服务器：Windows（Windows Service 自启）；制作机：Windows CLI。
- CR-02 多 IP：支持节点多网卡直连公网与路由器多公网 IP 映射两种来源，地址表可配置。
- CR-03 文件格式跨平台：`.gameindex` 与 pack 采用明确二进制规范（固定大小端、对齐）。

## 4. 废弃需求（DR）

- DR-01 客户机轻量 P2P 上传服务（客户机出界）。
- DR-02 Redis 缓存/队列（一期纯 redb + 内存）。
- DR-03 容器化部署（任何期不做）。
- DR-04 IPNI/storetheindex（暂缓，后续单独评估）。
- DR-05 内容加密（内容非机密，QUIC/TLS 已加密传输）。
