## 6. 二期规划：兜底数据中继（无盘中继）

> 一期不做，仅设计；一期代码预留扩展点见第 8 节。

### 6.1 定位与边界

- 部署在“网络带宽充足、但无业务磁盘能力”的位置（专线接入点/边缘机房），作为 IDC 不足或直连失败时的数据中转兜底。
- 复用网吧/IDC 提供方的磁盘 IO 与读取能力，中继只消费网络带宽，不落盘、不持久化任何业务块。
- 与一期 relay 职责分离：一期 relay 只打洞不传数据；兜底中继只传数据不打洞。
- 不改变主路径优先级：IDC 映射直连 → 网吧打洞直连 → 兜底中继；中继仅在源不可达、打洞失败或带宽受限时启用。

### 6.2 部署形态

- 硬件基线：专线/多网卡（10Gbps 起步）、内存 32-64GB（块级缓冲）、系统盘仅承载系统、CPU 满足 QUIC 加解密与转发。
- 位置：运营商边缘机房、专线汇聚点、CDN 式接入点；每区域至少 1 台，可多活。
- 进程：独立服务 `fallback-relay`（Linux，`bin/linux/`），只依赖调度中心控制面，无本地业务存储。
- 与现有 relay 可同机房共存，但进程独立、职责分离。

### 6.3 网络模型

- 控制面：gRPC 连接调度中心；注册（角色、区域、带宽、并发上限）、心跳、任务下发、统计上报。
- 数据面：QUIC 双向流（与一期同套传输体系）；中继是“转发器”而非“提供方”。
- 连接关系：
  - 下载方 C → 中继 R：C 直连 R 的公网/映射地址（R 在公网，无需打洞）；
  - 中继 R → 提供方 P：P 是网吧时由 P 向 R 打洞或直连（R 在公网，P 打洞到 R 通常容易成功）；
  - R 内按“会话”绑定两条连接，逐块转发。
- 转发粒度：以块为单位，与一期块协议一致；内存缓冲 1~2 个块；利用 QUIC 流控实现背压。
- 双重校验：R 收到块先 BLAKE3 校验与请求哈希一致再转发；C 端仍做最终校验，防止中继被注入错误数据。

### 6.4 会话与任务模型（调度中心）

- 新增任务类型 `relay_session`：
  - `source_node`（提供方）、`target_node`（下载方）、`relay_node`、`game_id`、`chunk_hash` 列表、配额（带宽/时长/字节）、优先级；
- 生命周期：创建（调度中心分派）→ 双方连接 R 并认证 → 协商会话令牌 → 逐块转发 → 校验与统计 → 关闭；
- 源选择扩展（在一期源选择之后追加第 3 级）：
  1. IDC 直连；
  2. 网吧打洞直连；
  3. 兜底中继 + 提供方组合（按区域、负载、带宽选择 R；按就近、负载选择 P）；
- 限流：R 按会话配额 + 全局并发/带宽上限执行；超限挂起或拒绝新会话；
- 失败处理：R 与 P 断连 → 自动重连 P；P 缺块 → 回源其他 P/IDC；R 过载 → 调度中心改派其他 R 或降级（下载方排队/只下载）。

### 6.5 安全与防滥用

- 中继是公共网络资源，必须认证：会话令牌由调度中心签发，一次性，绑定双方 endpoint_id、游戏、配额、有效期；
- R 只接受带令牌的会话；数据面 QUIC/TLS 加密；
- 每会话/每节点配额审计；超配额、请求未授权块等异常告警并断开；
- R 不落盘，最小化数据留存；日志仅保留会话元数据，不含块内容。

### 6.6 与前端管理界面的交互

- 新页面“中继管理”：
  - 实例列表：区域、在线状态、带宽利用率、并发会话、CPU/内存、版本；
  - 实例详情：实时流量曲线、会话列表、错误率；
  - 配置：全局带宽上限、每会话上限、并发上限、维护模式、启用/停用；
- 新页面“转发任务”：
  - 列表：发起网吧、提供方、中继实例、游戏、块数/字节、速率、状态、校验结果；
  - 详情：任务时间线（建连→传输→完成/失败）、每块校验结果、失败原因；
  - 操作：人工暂停/恢复/取消、重试；
- 统计报表：区域中继流量、节省 IDC 带宽估算、受益网吧排名、成本分析；
- 告警：中继过载、会话失败率突增、带宽超限、证书到期；
- 与一期页面衔接：节点管理增加“中继”类型筛选；任务页增加“中继任务”标签；全局审计日志覆盖中继操作；
- RBAC（二期一并实现）：超级管理员/运维/运营/只读，控制中继配置与任务操作权限。

### 6.7 一期预留项（现在留扩展点，二期再实现）

- proto：`NodeType` 预留 `FALLBACK_RELAY`；任务类型预留 `RELAY_SESSION`；节点注册预留 `region`、`bandwidth_mbps`、`max_sessions`、`capabilities`；
- 数据库：节点表预留角色/区域/带宽字段（一期可不加列，二期迁移）；
- 前端：节点类型、任务类型渲染由配置/枚举驱动，不硬编码死；
- 数据面：块请求消息已通用（game_id + 哈希列表），中继转发直接复用；请求头预留 `via_relay`/`session_token` 可选字段；
- 运维：部署文档记录“中继机房选型标准”（带宽、无盘、到网吧 RTT），供二期选址。

### 6.8 二期验收标准

- 两个网吧无法直连/打洞失败时，经中继完成整游戏下载，块哈希与源一致；
- 中继不落盘：进程重启后无业务数据残留；
- 并发 100 会话、单会话 500Mbps 下 CPU/内存/丢包达标；
- 前端可完成：实例启停、限流配置、任务查看/取消、报表导出；
- 中继故障自动改派/降级，不阻塞主路径。
