# BlazeNet 网吧游戏 P2P 分发系统 PRD

> 状态：v2.0（技术栈与更新流程整合版，待人工审核）
> 日期：2026-08-26
> 依据：01-立项说明书、02-结构化需求清单、PoC 验证结果

## 1. 整体业务说明

系统把游戏内容从制作机安全、高效地分发到全国网吧服务器：

1. 制作机对游戏文件分块（FastCDC）并计算哈希（BLAKE3），把差异块上传原始节点；
2. 原始节点与 IDC 以"每游戏一个块大文件"方式保存唯一块，跨版本共享；
3. IDC 按全局热度纳管游戏，块级多源互拉，优先其他 IDC、缺块才从中心拉；
4. 网吧服务器由管理员人工选择游戏，自动增量更新，用真实文件目录向无盘工作站提供内容；
5. 调度中心负责任务、块账本、热度、心跳、保活与后台管理。

## 2. 用户角色

| 角色 | 说明 | 主要操作 |
| --- | --- | --- |
| 内容制作人员 | 制作机操作者 | 制作/上传新版本、提交发布 |
| 系统管理员 | 后台账号 | 账号/场所/分组管理、节点参数、任务下发、回滚 |
| 网吧网管 | 后台账号（同一后台） | 为自己管理的场所选择游戏下载 |
| IDC/原始节点运维 | 节点侧 | 部署、配置地址表与阈值 |

## 3. 核心业务流程

### 3.1 内容发布

```text
制作机（新文件+旧文件）
  → FastCDC 分块 + BLAKE3 → 生成差异块与 .gameindex
  → 批量查询已存在块（秒传）→ gRPC 上传缺失块（块级校验入库）
  → 上传中：调度中心临时禁止该游戏请求，取消进行中任务
  → commit 版本清单 → 原始节点校验引用块齐全 → 发布新版本
```

### 3.2 分发（中心 → IDC）

```text
发布后：调度中心按热度 + 容量生成纳管计划
  → 块集合按 IDC 分片，不同 IDC 同时拉不同文件/不同块
  → IDC 优先从其他 IDC 拉，无则从中心拉
  → 每完成一块上报块账本，立即可被其他 IDC 引用
  → 全部块齐 → 版本就绪
```

### 3.3 网吧获取/更新

```text
管理员勾选游戏 → 调度中心下发任务（无自动推送）
节点处理流程统一为：拉索引 → 对账本地内容 → 清理无引用临时块
  → 保留可复用块 → 下载缺失块 → 合并（临时扩展名 + 文件哈希校验 + 原子替换）→ 就绪
```

对账按"更新计划（UpdatePlan）"执行：对比新旧 `.gameindex`，得到新文件列表、内容变化文件列表、删除文件列表、需要下载的块列表（全局去重）；先下载缺失块，再逐文件合并，合并完成后删除旧文件，临时块按 24h 规则清理。详见《数据存储设计文档》§3.2。

### 3.4 回滚

```text
后台发起"回滚到上一版" → 节点拉旧版本索引 → 补齐缺失历史块 → 合并 → 上报完成
```

## 4. 状态流转

### 4.1 游戏版本状态

```text
上传中（禁止下载）→ 已提交待校验 → 已发布（可下载）→ 维护中（可选暂停）
```

### 4.2 节点下载任务状态

```text
排队 → 下载中 → 合并中 → 就绪
       ↓ 失败（3 次退避 + 换源后仍失败）
       失败（后台展示，人工重发）→ 排队
       ↓ 上传中保护/管理员暂停
       已取消（记录日志）
```

### 4.3 节点/地址状态

```text
在线（心跳 25s）→ 离线（连续 3 次未心跳）
地址可用（pong）→ 不可达（连续 3 次未 pong，从 peer 列表剔除）→ 恢复后自动加回
```

## 5. 关键规则与约束

### 5.1 网络与拓扑

- 原始节点仅服务 IDC；网吧服务器禁止直连原始节点（数据面）；
- relay 独立服务、每机房一个，只做打洞协助，不承载块数据（应用层路径门控）；
- IDC 端口映射直连、不需要打洞；网吧打洞失败只下载不上传；
- 打洞端口必须使用 10001-65535；
- 一期不限速；降速下载放二期；
- IDC 面向所有网吧开放，就近优先（RTT），跨市跨省可拉。

### 5.2 存储

- 原始/IDC：每游戏一个 `blocks.pack` + 每版本 `.gameindex`；同哈希块复用；每位置保留当前 + 1 个历史块；延迟压缩（垃圾占比阈值可配置，默认 30%，空间不足推迟）；
- 网吧：真实文件目录 + 临时块目录；合并文件同目录临时扩展名（`.new`）+ 文件哈希校验 + 原子替换；临时块保留 24 小时作为上传源，之后从真实文件偏移服务；
- 跨游戏不共享块（每游戏独立块库）。

### 5.3 调度

- 热度 = 启动次数（一期），5 分钟上报、10 分钟重算；开发期 mock；
- IDC 按热度纳管，空闲低于节点配置阈值停止纳管新游戏，已纳管游戏更新照常；
- 网吧人工选择，每节点并发游戏数按节点配置（默认 5），超出排队；
- 多源下载：全局去重、块唯一分配、失败回填、RTT 排序；一期不做动态抢占；
- 版本级发布；预热放二期。

### 5.4 控制面

- gRPC 长连接推送，断线重连全量对账；
- 心跳 25 秒、75 秒判离线；
- 多地址保活：25 秒一轮窗口均摊，连续 3 次失败剔除，轻量 UDP ping；
- 块级重试 3 次（1/2/4 秒）后换源；任务失败人工重发；
- 调度中心单实例 + 每日备份（redb 快照 + 配置）；块库不备份。

### 5.5 安全

- 后台：账号密码登录，用户-场所/分组多对多绑定；
- 后台前端：React（TypeScript）+ Vite + Ant Design 5，由调度中心托管静态资源；
- 控制面：节点 Token + TLS（内部 CA）；
- 数据面：iroh NodeId 身份认证；未注册节点不下发 peer 列表；
- 内容不加密（QUIC/TLS 已加密传输）；
- 关键后台操作写审计日志。

## 6. 异常场景与降级策略

| 异常 | 处理 |
| --- | --- |
| 单块下载失败 | 重试 3 次（1/2/4s）后换源，交回全局缺失集合重新分配 |
| 游戏任务整体失败 | 状态置"失败"，后台展示，人工重发 |
| 节点离线 | 其未完成责任块由调度器重新分配；恢复后对账补齐 |
| 网吧打洞失败 | 只下载不上传；缺失块从 IDC 补 |
| relay 不可用 | 该区域打洞协助失效，网吧降级为只下载；IDC 主链路不受影响 |
| 调度中心宕机 | 新任务暂停；存量服务不受影响；重启后对账恢复 |
| 磁盘低于阈值（IDC/网吧） | 停止纳管/阻止新增（管理员可强制覆盖），已纳管更新照常 |
| 原始节点磁盘低于阈值 | 拒绝新上传并告警，不自动清理 |
| 合并文件校验失败 | 删除 `.new`、保留旧文件、重试该文件，多次失败告警 |
| 全网 IDC 均无某游戏 | 后台标"暂不可下载"，不做自动补拉 |
| 上传中访问游戏 | 请求被拒绝，进行中任务取消并记录日志 |

## 7. 性能要求（一期验收线）

1. 发布 50GB 新游戏，10~30 台 IDC 全部就绪，中心出口约等于一份全量；
2. 20GB 游戏仅 2GB 内容变更，网吧实际下载量 ≈ 2GB 差异块；
3. 多源下载：同一块不重复请求、失败回填、块校验失败重试；
4. 临时块 24 小时后删除，后续从真实文件偏移正常服务；
5. 回滚上一版后，文件哈希与旧版本索引一致。
