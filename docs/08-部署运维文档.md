# BlazeNet 部署运维文档

> 状态：一期草案（M8 前完善）。覆盖 Linux 服务与 Windows 程序部署、端口清单、systemd 示例、日常运维。

## 1. 交付物目录规范

- 所有编译交付物放置 `bin/` 目录，按平台分子目录：
  - `bin/linux/`：原始节点、各 IDC 节点、调度中心、relay（仅 Linux）；
  - `bin/windows/`：制作机、网吧服务器程序（仅 Windows）。
- Linux 可执行文件有且仅有一个参数 `--config <配置文件路径>`，其余配置全部在 TOML 配置文件中。
- Windows 可执行文件自动读取程序目录上一级目录下的 `config/<固定文件名>.toml`，文件名写死在代码中（如 `cafe-agent.toml`）。
- 所有注释、错误信息、日志、打印均为简体中文。

## 2. 拓扑与角色

| 角色 | 系统 | 说明 |
| --- | --- | --- |
| 原始节点（origin） | Linux | 单节点，保存全部游戏包/块，只服务 IDC |
| 调度中心（scheduler） | Linux | 一期与原始节点同机房；gRPC 控制面 + HTTP 后台/前端 |
| relay | Linux | 每机房一个；打洞信令 + QUIC 地址观测（只信令，不传数据） |
| IDC 节点（agent，idc） | Linux | 块库 + 多源下载 + 上传服务，映射地址直连 |
| 网吧服务器（agent，cafe） | Windows | 真实文件 + 差异块临时目录；NAT 打洞上传/下载 |
| 制作机（producer） | Windows | 游戏打包、差异生成、上传原始节点 |
| 地址回显服务（stun-echo） | Linux | 部署在 relay 主机（UDP），供节点启动期探测公网地址 |

## 3. 端口清单

| 服务 | 端口 | 协议 | 说明 |
| --- | --- | --- | --- |
| relay | 8443 | TCP | HTTPS relay 服务（443 被运营商屏蔽，改用自定义端口） |
| relay | 7842 | UDP | QUIC 地址观测（QAD），配合 observed address reports |
| relay 主机 | 8443 | UDP | 地址回显服务（可选，agent `stun_addr` 指向） |
| 调度中心 | 50051 | TCP | gRPC 控制面（注册/心跳/任务流） |
| 调度中心 | 18080 | TCP | HTTP 后台 + 前端静态托管 |
| agent（IDC） | 42001 | TCP/UDP | 数据面 iroh（端口可配置，NAT 网关需映射） |
| agent | keepalive_port | UDP | 保活 pong 应答（独立端口，需映射/可入站） |
| 打洞 | 10001-65535 | UDP | NAT 网关约束：10000 及以内不可打洞 |

云安全组/防火墙需放行：relay 的 TCP 8443、UDP 7842；调度中心 TCP 50051、18080；IDC 节点映射端口（如 42001）的 TCP/UDP；各节点 keepalive UDP 端口。

## 4. Linux systemd 部署示例

### 4.1 relay（官方 iroh-relay 1.1.0）

```toml
# /opt/blazenet/relay.toml
enable_relay = true
enable_quic_addr_discovery = true
http_bind_addr = "0.0.0.0:8080"
metrics_bind_addr = "0.0.0.0:9090"
key_cache_capacity = 1024

[tls]
https_bind_addr = "0.0.0.0:8443"
quic_bind_addr = "0.0.0.0:7842"
cert_mode = "Manual"
cert_dir = "/opt/blazenet"
manual_cert_path = "/opt/blazenet/relay-cert.pem"
manual_key_path = "/opt/blazenet/relay-key.pem"
```

```ini
# /etc/systemd/system/blazenet-relay.service
[Unit]
Description=BlazeNet Relay
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/opt/blazenet/relay-bin --config-path /opt/blazenet/relay.toml
Restart=on-failure
RestartSec=3
LimitNOFILE=1048576

[Install]
WantedBy=multi-user.target
```

生产证书：自签证书仅用于 PoC；上线前改用 ACME（LetsEncrypt）或受信任 CA 证书。

## 5. Windows 部署（网吧服务器/制作机）

- 程序目录结构：

```text
BlazeNet/
├── bin/windows/
│   ├── cafe-agent.exe
│   └── producer.exe
└── config/
    ├── cafe-agent.toml
    └── producer.toml
```

- 配置文件名固定（写死在代码中），程序启动自动读取 `bin/windows/../config/<固定名>.toml`。
- 建议注册为 Windows 服务（一期可用 `sc create` 或 NSSM 封装；正式交付提供安装脚本）。
- 网吧 agent 示例配置：

```toml
node_type = "cafe"
data_dir = "D:\\BlazeNet\\games"

chunk_concurrency = 4
disk_free_threshold = 200000000000
compact_threshold = 0.3
```

## 6. 日常运维

- 健康检查：`curl http://127.0.0.1:18080/healthz`；relay：`curl -k https://127.0.0.1:8443/healthz`。
- 节点状态：`curl http://127.0.0.1:18080/api/nodes`；任务状态：`/api/tasks`。
- 心跳：默认 25s，离线判定 75s；keepalive UDP 默认 25s 窗口、连续 3 次失败标记不可达。
- 任务下发（联调）：`POST /api/tasks`，body `{"node_id":4,"game_id":1,"version":2,"kind":"UPDATE"}`。
- 数据备份：调度中心内置每日 JSON 快照（配置 `backup_dir`，启动即备份一次，之后按 `backup_interval_hours` 周期备份）；redb 数据目录可另做冷备；节点块库按需备份。
- 日志：各服务 stdout 由 systemd journal 收集（`journalctl -u <服务名>`）。
- 安全基线：修改默认 admin 密码；relay/调度中心仅放行必要端口；生产使用受信任证书。

## 7. 二期预留

- relay 中继模式开关（`signaling_only` / `signaling_and_relay`）与兜底数据中继部署，见 04-开发计划与任务拆解 §6。
- 前端二期拆分：一期由调度中心自承载，二期前后端分离（Nginx 托管前端 + 反代后端）。

## 8. 节点准备清单（由用户单独提供）

> 约束：relay/调度测试主机只跑 relay 与调度中心，不运行原始节点、IDC、制作机等高 IO 功能。

### 8.1 原始节点 ×1（Linux）

- 操作系统：主流 x86_64 Linux（Alma/Rocky/Debian/Ubuntu），提供 root SSH 访问；
- 磁盘：建议 ≥1TB NVMe（按游戏目录规模；联调 mock 阶段 ≥80GB 可用）；
- 内存：≥16GB；CPU：≥8 核（FastCDC 分块 + BLAKE3 哈希）；
- 网络：≥1Gbps 公网出口；若有多公网 IP 一并提供（多 IP 分流）；
- 角色说明：保存全部游戏块库，只服务 IDC 节点，不直接服务网吧。

### 8.2 IDC 节点 ×N（Linux）

- 每台硬件同原始节点基线；磁盘按“中心游戏热门度”同步，建议 ≥500GB NVMe 起步；
- 网络：≥1Gbps 公网出口；多公网 IP 一并提供；
- 若位于 NAT 之后，提供公网映射地址与端口清单。

### 8.3 访问信息模板（每台节点提供一份）

```text
角色：origin / idc
别名/区域：如 idc-shanghai
公网 IP：x.x.x.x
SSH 端口：22（或自定义）
SSH 账号/密码：root / xxx（或密钥）
磁盘可用：xxx GB
内存/CPU：xx GB / xx 核
公网映射端口（TCP/UDP）：42001 等
多 IP 地址表：ip1、ip2...
```

## 9. 端口映射清单（每台节点）

| 端口 | 协议 | 用途 | 原始节点 | IDC 节点 | 映射要求 |
| --- | --- | --- | --- | --- | --- |
| 50052 | TCP | 上传 gRPC（制作机→原始节点） | ✅ | - | 制作机可直连（内网或公网映射） |
| 42001 | TCP/UDP | 数据面 iroh（拉块/上传） | ✅ | ✅ | 必须公网映射（NAT 后） |
| 42002 | UDP | keepalive pong（调度中心探测） | ✅ | ✅ | 必须公网映射 |
| 22（或自定义） | TCP | SSH 运维 | ✅ | ✅ | 运维可达 |

出站端口（无需入站映射）：调度中心 50051（gRPC）、relay 8443（TCP）/7842（UDP）、地址回显 8443（UDP）。

打洞约束：所有用于打洞的 UDP 端口必须在 10001-65535 之间（NAT 网关限制 ≤10000 不可打洞）。

调度中心/relay 主机端口（用户已放行）：relay TCP 8443、UDP 7842、UDP 8443（地址回显）；调度中心 TCP 50051、18080。
