# BlazeNet 测试用例文档

> 状态：一期草案（M7 联调前完善）。覆盖自动化门禁、模块单测、M7 验收五条、NAT/打洞与运维用例。

## 1. 自动化门禁（CI 强制）

1. 格式：`cargo fmt --check`；
2. 静态检查：`cargo clippy --workspace --all-targets -- -D warnings`；
3. 单元测试：`cargo test --workspace --all-targets`，全部通过；
4. 覆盖率：`cargo llvm-cov --workspace --lib --lcov`，`/crates/` 下 `DA:` 计数为 0 的行数必须为 0（100%）；
5. 构建：Linux 交付物（原始节点/调度中心/agent/relay）与 Windows 交付物（制作机/网吧 agent）均需成功；
6. Web 前端构建成功。

## 2. 模块级单测覆盖点

| 模块 | 关键用例 |
| --- | --- |
| blaze-common | 清单序列化/哈希、UpdatePlan 合并、保活报文编解码（BLZPNG/BLZPONG 往返、非法包） |
| blaze-proto | 控制面消息字段完整性 |
| producer | 分块（FastCDC）、差异清单生成、上传分包/校验、压缩 |
| origin | pack 追加/合并、redb 索引、垃圾压缩阈值、上传服务流式处理、commit 校验与原子替换 |
| scheduler | 数据层 CRUD、多对多绑定、块账本、保活状态机与探测循环（离线/恢复）、gRPC 注册/心跳/watch、REST 接口、任务推送 |
| agent | 配置解析（Linux/Windows 路径、端口校验）、数据面批量拉块与缺失块、路径门控（relay-only 拒绝）、下载调度（去重/分配/回填/RTT）、STUN 地址探测、pong 应答、控制面注册/心跳/任务接收 |
| relay | 占位入口（打洞协助由官方 iroh-relay 承担） |

## 3. M7 验收五条

### 3.1 发布 50GB 中心一次

- 前置：制作机生成 50GB 游戏包（或分批抽检大文件），上传原始节点；
- 步骤：制作机 → 原始节点 → 调度中心发布（commit 校验）→ IDC 按热度同步；
- 通过标准：中心一次发布成功；索引、块账本、版本号一致；任意抽检块 BLAKE3 与制作机一致。

### 3.2 增量 2GB 差异

- 前置：某版本基线已发布并同步到 IDC/网吧；
- 步骤：制作机生成新版（改动约 2GB），生成差异块并发布；
- 通过标准：节点只下载差异块；合并后文件哈希与制作机最新版一致；差异率/压缩率记录在案。

### 3.3 多源去重与回填

- 场景：多个 IDC 同时拉同一游戏不同块/同块不同块段；
- 验证：全局去重（同块只分配一次）、唯一分配（不重复拉同块）、失败回填（源失败后重新分配）、RTT 排序（就近优先）；
- 通过标准：无重复传输日志；任一块只由一个源承担；源失败后任务自动回填到待下载集合。

### 3.4 临时块 24 小时后偏移读

- 前置：网吧服务器下载差异块到临时目录；
- 步骤：块下载完成立即提供上传；整游戏差异块齐全后合并到真实文件；临时块保留 24 小时；
- 通过标准：24 小时内临时块可被上传服务读取；过期删除后，同哈希请求改读真实文件偏移，数据与哈希一致。

### 3.5 回滚哈希一致

- 步骤：从版本 N+1 回滚到 N；
- 通过标准：回滚后真实文件哈希与版本 N 一致；索引/版本号正确；节点可继续为后续版本提供差异源。

## 4. NAT 与打洞用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| NAT-01 | IDC 映射端口直连下载 | 直连建立，拉块哈希通过 |
| NAT-02 | 网吧全锥/端口受限锥形打洞上传 | 双向通告 external_addr（或 STUN 自动发现），direct 路径建立 |
| NAT-03 | 打洞失败（对称 NAT） | 连接保持 relay-only，数据面拒绝传块，下载方降级只下载 |
| NAT-04 | 地址回显服务（STUN） | 节点启动无 external_addr 也能发现公网地址并注册（kind=stun） |
| NAT-05 | relay-only 路径门控 | `paths()` 无 IP 路径时拒绝块传输；直连就绪后放行 |
| NAT-06 | 双网吧双向打洞 | 任一方向打洞成功后，直连连接双向复用，无需反向再次打洞 |

## 5. 控制面与运维用例

- 注册/心跳：节点注册后 online；25s 心跳持续刷新；停止心跳 75s 后离线（或 keepalive 连续 3 次失败离线）；
- 保活 UDP：调度中心 ping → 节点 pong → 状态保持 online；杀掉节点 → 自动 offline → 重启恢复；
- 任务下发：REST 创建任务 → gRPC 推送 → agent 收到（日志可见）；
- 多 IP 分流：节点多地址登记；调度中心按地址表下发；保活只探测 kind=config 的可入站地址；
- 弱网/断点：传输中断后只重传失败块；并发游戏数/块并发数按节点配置限制与排队；
- 前端：登录、节点/游戏/任务/状态页可查看；节点状态与后端一致。

## 6. 性能指标（试点参考）

- 单块拉取：1MiB 级块在 IDC 直连下吞吐不低于专线带宽的 80%；
- 并发：单节点默认 5 个游戏、每游戏 4 块并发，可配置；
- 多源：下载方同时从多源拉不同块，全局去重生效；
- 保活：25s 窗口均摊，单调度中心万级地址探测无峰值冲击。
