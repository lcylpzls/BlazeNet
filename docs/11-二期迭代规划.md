# BlazeNet 二期迭代规划

> 状态：草案（供人工审阅）
> 日期：2026-08-26
> 依据：一期 M7 验收报告（docs/10）、管理交互设计（docs/12）

## 1. 二期目标

一期解决了"内容能到网吧"；二期解决"调度更聪明、网络更省、运维更稳、交互更完整"。

核心目标：

1. 全局块责任分片：中心出口严格"每块一次"，多 IDC 并发时自动分工、失败回填、动态抢占；
2. 网络成本控制：带宽时段限速、不上传降速下载、预热、跨地域流量调度、多 IP 分流；
3. 可靠性升级：兜底无盘中继、节点磁盘容量自动纳管、断点续传对账、远程自升级；
4. 可观测与安全：Prometheus/Grafana、RBAC、审计分级、TLS 证书管理；
5. 内容效率：文件级差分、1GB 分段压缩、文件重命名/内容级复用识别、历史版本治理；
6. 管理与交互：制作机独立操作台 + 云端 Web 统一管理（详见 docs/12）；
7. 性能底座：评估 compio（io_uring/IOCP）、更高吞吐数据面、并发压测。

## 2. 迭代批次

### P2.1 智能调度与控制面（先做，依赖最重）

| 任务 | 说明 | 验收 |
| --- | --- | --- |
| 全局块责任分片 | 调度中心按版本清单把缺失块分片给 IDC，同块只分配一次；节点按 assigned_chunks 拉取 | 多 IDC 并发拉同一游戏，中心出口每块仅一次 |
| 任务抢占与动态调整 | 新任务可抢占低优任务；节点离线后责任块重新分配 | 离线/恢复场景账本一致 |
| 节点容量自动纳管 | 按热度 + 磁盘空闲阈值自动下发/淘汰游戏 | 磁盘阈值生效且不超卖 |
| 多 IP 分流 | 节点多公网地址注册、按地址/链路负载分配数据流 | 多地址并行下载吞吐提升 |
| 带宽时段限速 | 按节点/区域/时段配置上下行限速 | 限速曲线生效 |
| 断点续传与全量对账 | 任务中断后按账本续传；重连后节点持有块与调度账本对账 | 断网恢复后只补缺失块 |

### P2.2 兜底中继与降级

| 任务 | 说明 | 验收 |
| --- | --- | --- |
| 无盘中继服务 | 网络充足、无业务磁盘位置部署；会话级转发、不落盘 | 两网吧无法直连时经中继完成下载，进程重启无残留 |
| 中继模式开关 | 每 relay 可配置信令 only / 信令+中继，前端可切换 | 切换后新任务立即生效，存量会话按策略结束 |
| 打洞失败降速下载 | 网吧打洞失败只下载不上传，并对下载限速 | 对称 NAT 场景可控降速 |
| 中继会话管理 | 并发上限、带宽上限、会话超时、失败重试、审计 | 100 会话/500Mbps 达标 |

### P2.3 可观测与安全

- Prometheus/Grafana：节点/任务/块账本/中继/带宽指标大盘；
- 结构化日志与错误码：统一日志格式、错误分级、日志采集；
- RBAC：超级管理员/运维/运营/只读，接口与页面权限矩阵；
- 审计增强：登录、导出、配置变更、任务操作全留痕；
- TLS/证书：内部 CA 自动续期、中继证书管理；
- 远程自升级：Linux systemd + Windows 服务原子升级、灰度与回滚。

### P2.4 内容效率

| 任务 | 说明 |
| --- | --- |
| 文件级差分 | 对大型二进制（引擎包等）在块级之上做文件级 diff |
| 1GB 分段压缩 | 大文件按 1GB 分段 + 压缩，降低中心出口与存储 |
| 重命名/内容级复用识别 | 文件移动/改名不重传内容 |
| 历史版本治理 | 按策略保留 N 个版本、延迟删除、历史块压缩 |
| 制作机增量加速 | 基于上一版本目录做增量分块，减少制作时间 |

### P2.5 管理与交互（详见 docs/12）

- 制作机独立操作台（Windows GUI）；
- 云端 Web：工作台、节点、游戏、任务、中继、监控、审计、系统设置；
- 前后端分离：前端 Nginx 托管，后端反向代理；
- 前端健壮性迭代：统一请求封装、轮询/WebSocket、并发冲突提示、权限路由。

### P2.6 性能与架构

- compio 评估与高 IO 路径替换（io_uring/IOCP）；
- 数据面批量流式、多连接并发、零拷贝；
- 调度中心 openraft 三节点 HA；
- 多原始节点/分片（发布带宽扩容）；
- 万级节点压测：注册、心跳、保活、任务流。

## 3. 新增需求建议（超出原二期清单）

1. **全局块分片调度**（原一期遗留，二期必做）；
2. **多 IP 数据面分流**（一期仅地址表，二期做流量级分流）；
3. **无盘中继计费/成本报表**（中继流量、节省带宽估算）；
4. **节点健康评分**（磁盘、带宽、在线率、贡献度），影响选源优先级；
5. **内容白名单/合规**（游戏版本审核、上传审批流）；
6. **客户端灰度**（游戏更新按场所分组灰度、回滚开关）；
7. **离线网吧预取**（按历史启动行为在低峰预拉热门游戏）；
8. **块级压缩缓存**（跨游戏重复块共享统计）；
9. **制作机双机热备/远程制作**（制作任务可委派）；
10. **Windows 服务封装**（二期/三期收尾统一实施，一期用控制台）。

## 4. 二期验收标准

- 多 IDC 并发拉同一游戏，中心出口每块一次（日志+账本可证明）；
- 中继降级、打洞失败降速、带宽限速均生效；
- 管理端可完成全部运维操作；RBAC 权限矩阵通过；
- 万级节点控制面压测达标；Prometheus 大盘可用；
- 覆盖率 100% 门禁保持；CI/Release 全绿。

## 5. 排期建议

P2.1 → P2.2 → P2.3 → P2.4 → P2.5 → P2.6，其中 P2.1 与 P2.5 可部分并行（调度 API 与前端交互同时设计）。
