# BlazeNet 一期 M7 验收报告

> 状态：已执行（2026-08-26）
> 里程碑：v0.1.0
> 说明：受测试主机磁盘与公网映射限制，数据规模按比例缩减，验收逻辑与链路不变。

## 1. 验收环境

| 角色 | 主机 | 说明 |
| --- | --- | --- |
| 原始节点 | 10.117.111.101 | 上传 gRPC 50052 + 数据面 42001 |
| 调度中心 | 124.221.250.139 | gRPC 50051 + HTTP 18080，含每日备份 |
| IDC（验收） | 10.117.111.101（idc-data） | 从原始节点拉取，供网吧互拉 |
| 网吧服务器 | 10.117.111.113 | Linux 控制台版 agent，真实文件 + 临时块 |
| 外网 IDC1/IDC2 | 111.161.74.28 / 221.1.133.38 | 已部署，因原始节点公网 UDP 映射不可达暂未完成外网联调 |

验收数据：3 个模拟游戏（11/12/13），每个约 1.8GB、150 个文件，包含大文件、中文件、小文件与多层目录嵌套。总量约 5.4GB（正式 50GB 规模按同链路等比外推）。

## 2. 验收五条结果

### 2.1 全量发布（中心一次）

- 制作机分别生成 1662/1666/1694 个块并上传原始节点，commit 校验通过后自动发布到调度中心；
- IDC 从原始节点全量同步，pack 大小与原始节点一致（11: 1837006848 字节；12/13: 1837004800 字节）；
- 网吧从 IDC 互拉完成三个游戏，每个游戏 150 个文件，抽查 sha256 与制作机源文件一致；
- 中心出口每块只下发一次（IDC 拉取后网吧改从 IDC 拉取）。

**结论：通过（数据规模按 50GB→5.4GB 等比缩减）**

### 2.2 增量 2GB 差异

- 游戏 11 v2 仅修改 1 个小文件；
- 制作机生成 1 个差异块并发布；
- IDC 与网吧只下载 1 块差异块，网吧合并后文件哈希与 v2 一致，current.version=2。

**结论：通过**

### 2.3 多源去重与回填

- 端到端：IDC→原始节点，网吧→IDC，peer 列表与块账本生效；
- 下载调度（唯一分配/失败回填/RTT 排序）由单元测试覆盖并通过；
- 块账本支持多持有者，网吧上传源（临时块→真实文件偏移）实测可被拉取。

已知改进项：调度中心侧"同块只分配一次"的全局责任分片尚未实现（当前由创建任务顺序保证中心一次），列入二期 P2.1。

**结论：基本通过（全局分片入二期）**

### 2.4 临时块 24 小时后偏移读

- 网吧 v2 差异块先以临时块提供上传（2048 字节，哈希校验通过）；
- 删除临时块后再次拉取，自动回退真实文件偏移读，数据一致；
- 24 小时过期清理逻辑与周期任务由单元测试覆盖。

**结论：通过**

### 2.5 回滚哈希一致

- 通过回滚接口 `POST /api/games/{id}/rollback` 将网吧游戏 11 从 v2 回滚到 v1；
- current.version=1，回滚后文件 sha256 与 v1 一致。

**结论：通过**

## 3. 过程中发现并修复的极端问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 大块上传提交时"块未齐全" | FastCDC 最大块 4MiB+44B 超过 tonic 默认 4MB 消息上限，服务端静默断流 | 上传服务与客户端消息上限提升到 16MiB |
| 网吧合并部分文件丢失但任务显示成功 | 磁盘写满导致 write 失败，合并失败被忽略 | 合并失败显式上报并置任务失败 |
| 同版本重跑无法修复缺失文件 | 合并仅按清单哈希差异判断 | 目标文件不存在时强制补块重合并（自动修复） |
| 并发任务无源时报错不明确 | peer 地址为空时视为无源 | 报错信息包含游戏与缺失块数 |

## 4. 遗留环境事项

1. 原始节点公网 UDP 42001 映射不可达，外网 IDC1/IDC2 数据面直连超时；待用户修复映射后按本报告流程复跑；
2. 50GB 正式规模需在磁盘充足的测试机上复测，本报告为等比缩规模验收；
3. 调度中心侧全局块责任分片、网吧 24h 清理的"过期再验证"等列入二期。
