# BlazeNet 网络协议与接口设计文档

> 状态：v1.0（待人工审核）
> 日期：2026-08-26
> 依据：05-系统架构设计文档、06-数据存储设计文档

## 1. 协议总览

| 链路 | 协议 | 说明 |
| --- | --- | --- |
| 节点 ↔ 调度中心（控制面） | gRPC over TLS（tonic 0.14） | 注册/心跳/任务推送/账本/秒传查重 |
| 制作机 ↔ 原始节点（上传） | gRPC 双向流 | 块级断点续传 + commit |
| 节点 ↔ 节点（数据面） | iroh 1.0 自定义 ALPN | 批量块请求/流式响应 |
| 调度中心 ↔ 节点（保活） | 轻量 UDP ping/pong | 独立端口，与数据面分离 |
| 浏览器 ↔ 后台 | HTTP（REST JSON） | 由调度中心托管 |

## 2. 通用约定

- 时间：i64 毫秒时间戳；
- 哈希：BLAKE3 32 字节，小端原样传输；
- ID：u64；版本号：u64（单调递增）；
- 错误：gRPC 使用 status code + message；业务错误码统一表（见 §6）；
- 认证：控制面请求带 `authorization: Bearer <token>`；TLS 内部 CA。

## 3. 控制面 gRPC 接口（proto 草案）

```protobuf
syntax = "proto3";
package blazenet.control;

service Control {
  // 节点注册（启动时；返回 token 与初始任务）
  rpc Register(RegisterRequest) returns (RegisterReply);
  // 心跳 + 摘要对账（25s 一次）
  rpc Heartbeat(stream HeartbeatRequest) returns (stream HeartbeatReply);
  // 任务流（长连接推送；重连后先全量拉取）
  rpc WatchTasks(TaskFilter) returns (stream TaskEvent);
  // 确认/上报任务状态
  rpc ReportTask(TaskReport) returns (Empty);
  // 块完成上报（每块一次，账本更新）
  rpc ReportChunk(ChunkDone) returns (Empty);
  // 查询候选源（含多 IP 地址，RTT 排序由请求方探测）
  rpc QueryPeers(PeerQuery) returns (PeerList);
  // 查询游戏版本与块清单
  rpc GetVersion(VersionQuery) returns (VersionInfo);
  // 秒传查重（制作机上传前批量查询已存在块）
  rpc QueryExistingChunks(ChunkQuery) returns (ChunkExists);
}

service Upload {
  // 制作机上传块：双向流，每块独立确认
  rpc UploadChunks(stream UploadChunk) returns (stream UploadAck);
  // 提交版本清单（commit；引用块齐全后发布）
  rpc CommitVersion(CommitRequest) returns (CommitReply);
}

message RegisterRequest { string node_type = 1; string endpoint_id = 2; repeated Addr addrs = 3; string token = 4; }
message RegisterReply { string token = 1; repeated Task initial_tasks = 2; }
message HeartbeatRequest { uint64 node_id = 1; Summary summary = 2; repeated AddrStatus addrs = 3; }
message HeartbeatReply { uint64 server_time = 1; repeated uint64 task_ids = 2; /* 需要重发的任务 */ }
message TaskEvent { oneof ev { Task task = 1; TaskCancel cancel = 2; } }
message Task {
  uint64 id = 1; uint64 game_id = 2; uint64 version = 3;
  enum Kind { DOWNLOAD = 0; UPDATE = 1; ROLLBACK = 2; }
  Kind kind = 4; repeated bytes assigned_chunks = 5; // 责任块（哈希列表）
}
message TaskCancel { uint64 task_id = 1; string reason = 2; }
message ChunkDone { uint64 node_id = 1; uint64 game_id = 2; bytes chunk_hash = 3; uint32 size = 4; }
message PeerQuery { uint64 game_id = 1; bytes chunk_hash = 2; uint32 limit = 3; }
message PeerList { repeated Peer peers = 1; }
message Peer { uint64 node_id = 1; string endpoint_id = 2; repeated Addr addrs = 3; bool direct_only = 4; }
message Addr { string addr = 1; string kind = 2; string link = 3; }
message UploadChunk { uint64 game_id = 1; bytes chunk_hash = 2; bytes data = 3; uint32 seq = 4; }
message UploadAck { bytes chunk_hash = 1; bool ok = 2; string error = 3; }
message CommitRequest { uint64 game_id = 1; uint64 version = 2; bytes manifest = 3; bytes manifest_hash = 4; }
message CommitReply { bool published = 1; string error = 2; }
```

> 以上为草案，编码阶段按此生成 `proto` 文件；REST 后台接口由后台模块另行列出（账号/场所/分组/节点/游戏/任务/状态/审计）。

## 4. 数据面 iroh 自定义协议

- ALPN：`blaze-poc/1`（正式版改为 `blazenet/1`）；
- 打洞双方都必须通告可达公网地址（`external_addr`，含 NAT 映射地址）；只通告内网地址时，对端打洞探测会打向内网地址，直连无法建立（实测结论）；
- 连接建立后先检查路径：`Connection::paths()`；若直连路径未就绪，服务端等待最多 30 秒再判定；`!has_direct && has_relay` → 拒绝块传输（relay 只打洞）；
- 对称型 NAT 出口端口分配不稳定（同一端口有时保留、有时不保留），打洞成功率取决于提供方 NAT 是否保留端口；网吧 NAT 按全锥/端口受限锥形评估，IDC 网络按映射地址直连评估，不依赖对称 NAT 打洞；
- 批量请求（客户端 → 服务端，双向流 send 侧）：

```text
u32 chunk_count
repeat chunk_count:
    bytes[32] chunk_hash
```

- 流式响应（服务端 → 客户端，同一流的 recv 侧）：

```text
repeat chunk_count:
    u32 compressed_len
    bytes  compressed_data        // zstd 快速级；标志位在版本头协商
```

- 客户端逐块解压 + BLAKE3 校验；失败只重传该块；
- 支持中途取消（关闭流）；
- 响应错误：连接关闭前发送 `u32 0xFFFFFFFF + u16 error_code + bytes message` 作为终止帧；
- 传输不加密内容（QUIC/TLS 已加密）。

## 5. 保活 UDP ping 协议

- 端口：节点配置的独立 UDP 端口（默认 42001 + 偏移，可配置）；
- 帧格式：`magic "BLZPNG" (6B) | u32 seq | u64 node_id | u32 addr_index`；
- 响应：`magic "BLZPONG" (7B) | u32 seq`；
- 调度中心按 25 秒窗口均摊探测（每地址在窗口内均匀分布）；连续 3 次无响应标记不可达；恢复后自动加回；
- 只探测声明可入站的地址（IDC/原始节点直连地址、网吧映射端口）；打洞地址不探测。

## 6. 错误码表（业务级）

| code | 含义 | 典型场景 |
| --- | --- | --- |
| 1001 | 未认证/Token 失效 | 控制面请求 |
| 1002 | 节点未注册 | 注册前调用 |
| 1101 | 游戏不存在 | 任务/查询 |
| 1102 | 版本不存在 | 索引/回滚 |
| 1103 | 游戏上传中，禁止下载 | 发布保护 |
| 1201 | 块不存在 | 上传/下载 |
| 1202 | 块哈希校验失败 | 上传/下载 |
| 1203 | 块已存在（幂等） | 秒传 |
| 1301 | 磁盘空间不足 | 上传/纳管 |
| 1302 | 节点离线 | 任务下发 |
| 1303 | 地址不可达 | 保活/peer 列表 |
| 1401 | 任务不存在/已取消 | 上报 |
| 1402 | 任务状态非法 | 状态流转 |
| 1501 | 文件哈希校验失败 | 合并 |
| 1502 | 压缩空间不足，已推迟 | 压缩 |
| 1601 | 参数非法 | 通用 |

## 7. 异常示例

### 7.1 上传中断重传

```text
客户端: UploadChunk{seq=5, hash=X, data=...}
服务端: UploadAck{hash=X, ok=true}
网络断 → 客户端重连 → 重发 seq=5..N（已 ack 的跳过）
```

### 7.2 上传中保护

```text
节点: GetVersion{game_id=1, version=2}
调度中心: 1003 游戏上传中，禁止下载
节点: 收到 TaskCancel{task_id=10, reason="版本上传中"} → 取消任务并记日志
```

### 7.3 relay-only 拦截

```text
节点A(网吧) → 节点B(网吧): 连接建立
双方 paths(): relay=true, ip=false
→ 双方按策略均不打开块传输流；连接仅用于连通性确认
```
